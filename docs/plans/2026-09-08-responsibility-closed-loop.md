# 责任闭环切片 R（2026-09-08 起草）

> 背景：正式部门多人分工做数据治理。用户核心诉求——每步有"关键人"且不烂尾（闭环）。
> 现状：后端已有责任相关接口（GovernanceResponsibilityController 认领/分配/移交 PUT/GET）与
> 任务（执行人/验收责任人/计划日期）、通知中心（到期/逾期提醒雏形）；前端未接通批量分配/认领/移交，
> 无"我的待办/责任卡片"可视化；无真实登录（demo-user，D1 前置）。

## R1 管理员分派工作台（无登录即可用，先做）
- 治理中心新增"分派"入口：按 问题池/资料 批量勾选 → 指定执行人 + 验收人 + 到期日（打通已有任务/责任人接口）。
- 任务清单卡片化：执行人、验收人、到期/逾期徽标、进度。
- 移交/改派操作可用（管理员换人后原责任人解套）。
- 验收：管理员可完整走"建任务→分派→执行→验收"闭环（现 e2e 已覆盖治理闭环，需补责任分派用例）。

> R1a 实施（2026-09-08，commit 4e7c936 起）：治理轨道首屏"分派工作台"已完成 ——
> 六节点轨道 + 指标卡 + 该步待办 + 下一步建议 + 任务闭环明细；治理首页即工作台。
> R1b 实施（见下"R1b 任务移交"），R1 分派创建已由"字段问题池"批量勾选建任务承载。

### R1b 任务移交（2026-09-08 实施，本切片）

缺口：任务 owner（负责人）创建后即锁定（`applyMutableState` 保留原值、任务 PATCH 全拒），管理员无法换人解套。

落地：
- 后端 `POST /api/v1/governance/tasks/{taskId}/reassign`（body `{ownerUserId, expectedVersion}`）：
  仅闭环任务（LEGACY 只读拒绝）、未完成任务（COMPLETED 拒绝）、目标必须是员工目录成员、不能移交给当前负责人；
  owner 为创建后锁定字段，移交走 store 专用通道 `reassign`（InMemory/Jdbc 同语义，乐观锁推进版本），
  成功后 ownerUserId/ownerName/assigneeId 同步换人（domain 新增 `reassignTo`）。
- 前端：任务详情页顶部"移交"按钮 → 员工下拉弹层 → 提交后刷新任务与清单；已完成/历史任务不显示移交。
- 测试：controller 3 例（移交成功/同人或未知人拒绝/legacy 与版本冲突拒绝）、前端详情页 2 例（移交成功、完成态隐藏）+ api 契约。
- 验收路径：字段问题池勾选建任务 → 任务详情"移交"换负责人 → 启动 → 清洗 → 确认 → 验收（既有闭环 e2e 阶段 4 覆盖）。
