# 治理任务甘特图设计

## 目标

在治理任务详情中增加任务级甘特图，让内容管理员在一个视图中查看计划排期、责任人、完成比例、前置依赖和逾期风险。甘特图复用现有治理计划数据，不建立新的项目领域，也不改变计划启动后的锁定规则。

## 首期边界

首期只覆盖单个治理任务：

- 在“计划依赖与责任”区域提供“表格 / 甘特图”分段切换。
- 按计划开始和结束日期绘制时间条，展示责任人、计划数量和自动完成比例。
- 展示计划间的前置依赖连线，并对缺失依赖数据使用受控提示。
- 标记逾期、进行中、已完成和被前置计划阻塞的计划项。
- 展示业务确认、质量验收和正式应用的工作流里程碑状态。
- 草稿阶段继续使用现有表单新增计划；启动后甘特图和表格均只读。

首期不支持跨任务组合甘特图、拖拽改期、执行中变更计划、关键路径计算、资源负荷、基线版本对比或导出图片。里程碑没有独立计划日期，因此只展示工作流状态，不把它们伪造为时间轴上的日期节点。

## 方案比较

### 方案 A：原生时间轴与 SVG 依赖层

使用 React、CSS Grid 和一个独立 SVG 覆盖层绘制依赖连线。时间范围、条形位置、完成比例和风险状态由纯函数计算。

优点是没有新增运行时依赖，视觉能与当前 Ant Design 工作台保持一致，计算逻辑可以独立测试。缺点是需要自行处理时间尺度和连线定位。

### 方案 B：引入第三方甘特图库

使用通用甘特组件完成缩放、拖拽和依赖绘制。成熟库适合复杂排程，但通常自带编辑模型和视觉体系；本期只读、小规模计划会引入超出需求的包体、样式适配和升级成本。

### 方案 C：扩展当前表格

在表格中增加日期条和依赖文本。实现最小，但不能直观看到计划重叠、时间跨度和依赖方向，不满足甘特图的核心价值。

选择方案 A。它能完整覆盖首期只读场景，同时保持边界小且可测试。

## 页面结构

“计划依赖与责任”区域保留现有标题和计划编辑入口，并增加固定宽度的分段控件：

1. “表格”视图继续展示现有计划表及草稿编辑表单。
2. “甘特图”视图顶部展示任务排期摘要和工作流里程碑。
3. 主体左侧为固定信息列，显示计划名称、责任人和数量进度。
4. 主体右侧为可横向滚动的时间轴，计划行与信息列保持同高。
5. 时间轴内显示计划条、完成填充、今天线和依赖连线。

视图切换只影响本地展示状态，不触发请求，也不改变编辑状态。默认进入“表格”，避免改变现有用户习惯。

## 时间轴规则

时间范围取全部有效计划日期的最早 `plannedStart` 和最晚 `plannedEnd`，两端各增加一天视觉留白。没有完整起止日期的计划不参与时间范围计算，并在甘特图内列入“排期不完整”提示。

- 结束日期按包含当天计算，单日计划仍显示一个完整时间单元。
- 31 天以内按日显示主刻度；更长范围按周显示主刻度，但条形位置仍按自然日计算。
- 时间轴宽度设置稳定最小值并允许区域内横向滚动，不压缩计划名称或造成页面整体横向溢出。
- 完成比例为 `completedQuantity / plannedQuantity`，限制在 0% 到 100%；计划数量为零时显示 0%。
- 计划结束日期早于当前日期且未完成时标记为逾期。
- 计划存在未完成的前置计划时标记为阻塞；依赖关系只在当前任务内解析。
- `actualStart` 和 `actualEnd` 存在时用于辅助文本，不覆盖原计划条，也不改变计划基线。

## 工作流里程碑

里程碑条使用现有任务状态推导，不增加或写入日期：

| 里程碑 | 达成条件 |
| --- | --- |
| 计划锁定 | 任务已离开 `DRAFT` |
| 业务确认 | `PENDING_CONFIRMATION` 为进行中，`PENDING_ACCEPTANCE` 或 `COMPLETED` 为已完成 |
| 质量验收 | `PENDING_ACCEPTANCE` 为进行中，`COMPLETED` 为已完成 |
| 正式应用 | 任务为 `COMPLETED` |

`REWORK_REQUIRED` 只能证明任务进入返工，不能从当前状态判断退回发生在确认还是验收阶段。因此计划锁定保持已完成，其余里程碑显示待处理，并单独显示“返工中”警示。前端只做展示映射，不向后端回写里程碑。

## 组件边界

新增以下前端单元：

- `governanceGanttModel.ts`：纯函数，计算日期范围、刻度、条形位置、进度、逾期和阻塞状态。
- `GovernanceGanttView.tsx`：渲染计划信息列、时间轴、计划条、今天线、空状态和排期异常提示。
- `GovernanceDependencyLayer.tsx`：只负责根据已计算的行位置绘制依赖连线和箭头。
- `GovernanceMilestoneStrip.tsx`：根据任务状态展示工作流里程碑。
- `GovernancePlanEditor.tsx`：保留编辑职责，增加表格/甘特图切换并组合上述组件，同时展示计划查询的加载和失败状态。

甘特组件只接收已有 `GovernancePlan[]`、员工列表、任务状态和参考日期，不发起 API 请求。`GovernanceTaskDetailPage` 继续拥有查询和命令职责，并把计划查询的加载及错误状态传给计划工作区。

## 数据与接口

现有 `GET /api/v1/governance/tasks/{taskId}/plans` 已返回首期所需字段：

- `plannedStart`、`plannedEnd`
- `actualStart`、`actualEnd`
- `plannedQuantity`、`completedQuantity`、`quantityUnit`
- `responsibleUserId`
- `dependencyIds`
- `status`

因此首期不修改后端、数据库或 API 契约。若后续需要基线版本、里程碑日期或跨任务视图，再通过独立版本扩展领域模型。

## 异常与空状态

- 无计划时显示“尚未编排计划项”，草稿任务保留编辑入口。
- 全部计划均缺少有效日期时显示“计划排期不完整，暂无法生成甘特图”。
- 部分计划日期无效时绘制其余计划，并列出未进入时间轴的计划名称。
- 依赖 ID 不存在时不绘制错误连线，计划行显示“依赖数据异常”。
- 查询加载时显示明确加载状态；查询失败时显示错误提示，不能伪装为无计划。

## 可访问性与响应式

- 分段控件使用明确的“表格”和“甘特图”文本。
- 每个计划条提供包含计划名、日期、责任人、完成比例和状态的可访问名称。
- 颜色不是唯一状态信号，同时显示状态文字或图标。
- 计划行使用稳定高度，依赖层不参与页面布局，避免连线改变容器尺寸。
- 1366×768 下左侧信息列保持可读，时间轴只在自身区域横向滚动；1920×1080 下利用额外宽度展示更多日期。

## 测试与验收

纯函数测试覆盖：

- 单日和跨日计划的位置与宽度。
- 长短时间范围的日/周刻度。
- 完成比例边界、逾期判断和前置依赖阻塞。
- 缺失日期、反向日期和不存在依赖的受控结果。

组件测试覆盖：

- 默认显示表格并可切换到甘特图。
- 甘特图显示计划条、责任人、完成比例、里程碑和依赖关系。
- 无计划与排期不完整状态。
- 非草稿任务不能通过甘特图修改排期。

浏览器验收覆盖 1366×768 和 1920×1080：视图切换稳定，文本不重叠，页面无整体横向溢出，时间轴内部滚动正常，依赖连线与计划行对齐。

## 完成标准

- 用户可在单个治理任务详情中切换表格和甘特图。
- 所有有效计划按真实排期展示，进度来自治理项聚合结果，不允许手工伪造。
- 依赖、逾期、阻塞和工作流里程碑清晰可辨。
- 计划锁定规则保持不变，甘特图没有隐藏的写操作。
- 前端测试、lint、typecheck、build 和双桌面尺寸浏览器验收通过。
