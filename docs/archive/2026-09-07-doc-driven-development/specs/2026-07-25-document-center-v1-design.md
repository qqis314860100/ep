# 文档中心 V1.6.1 设计

## 目标

交付文档中心的第一个可运行闭环：文档维护者创建包含首个文件版本的草稿并发布，普通用户通过方案 A“检索工作台”查找已发布文档，进入独立详情页预览或下载当前有效版本。

## 版本边界

V1.6.1 包含：

- 文档分类字典和首期六类基础值。
- 知识文档、首个文档版本和版本文件。
- 草稿保存、首次发布、已发布文档搜索和详情查询。
- PDF、图片预览与其他允许格式下载。
- 文档中心检索工作台、文档新建页和独立详情页。
- 默认内存仓储、本地 MySQL 持久化结构和受控生产迁移脚本。

V1.6.1 不包含：

- 创建第二个及后续版本、历史版本切换。
- 资产文档关联和文档间引用。
- 文档收藏、评论、点赞和停用。
- 复杂审批、电子签章、生产批准和在线编辑。

这些能力分别进入 V1.6.2、V1.6.3 和 V1.6.4，避免首个版本同时引入多个独立闭环。

## 页面结构

### 文档检索工作台

- 侧栏一级导航新增“文档中心”，路径为 `/documents`。
- 页面内部左侧是稳定的文档分类导航，包含“全部文档”和启用分类，不使用多层页签。
- 主区顶部提供关键词搜索、分类、维护人和更新时间筛选；V1.6.1 的服务端先支持关键词和分类，未接入的筛选不显示假控件。
- 主区使用紧凑列表展示标题、编号、摘要、分类、当前版本、维护人、更新时间和可预览标识。
- 右上角提供“新建文档”命令，进入独立新建页，不在检索页中展开大型表单。
- 空状态、加载失败和搜索无结果分别提供明确反馈及重试/清空入口。

### 文档新建页

- 路径为 `/documents/new`，使用 Ant Design `Form` 与 `Upload.Dragger` 组成单页表单。
- 首次保存必填标题、分类、摘要、维护人和至少一个文件。
- 文档编号可以由维护者填写或由系统生成；发布前必须唯一。
- 版本号默认建议为 `V1.0`，首版变更说明默认“首次发布”，均允许发布前调整。
- “保存草稿”和“发布文档”是两个明确命令；发布前展示即将发布的编号、版本和文件清单。
- 离开存在未保存内容的页面时给出确认，不将文件选择与业务表单拆成页签。

### 文档详情页

- 路径为 `/documents/:id`，采用紧凑工作台：左侧版本文件列表、中间预览区、右侧文档信息。
- V1.6.1 只展示当前有效版本，不展示尚未实现的历史版本切换控件。
- PDF 和图片进入预览；其他格式显示文件摘要和下载命令。
- 页面明确展示“当前版本”、发布时间、维护人和文档状态。
- 资产关联与评论区域在对应版本实现前不展示占位卡片。

## 后端领域设计

### 知识文档

`KnowledgeDocument` 是稳定聚合根，包含：

- `id`
- `documentNumber`
- `title`
- `summary`
- `categoryCode`
- `maintainerId`、`maintainerName`、`maintainerDepartment`
- `status`：`DRAFT`、`PUBLISHED`、`DISABLED`
- `currentVersionId`
- `createdAt`、`updatedAt`
- `version`：乐观锁版本

### 文档版本

`DocumentVersion` 归属于知识文档，包含：

- `id`、`documentId`
- `versionNumber`
- `changeSummary`
- `status`：`DRAFT`、`PUBLISHED`、`HISTORICAL`
- 一个或多个 `DocumentFile`
- `createdBy`、`createdAt`、`publishedBy`、`publishedAt`

V1.6.1 每个文档只创建首个版本，但模型从一开始允许后续追加版本，避免 V1.6.2 修改稳定标识。

### 文件存储边界

文档领域不能依赖 `asset.application.AssetFileStorage`。V1.6.1 将文件存储接口和已存文件值对象提取到 `common.file`，资产与文档共同依赖该公共端口，现有内存、本地和只读适配器继续实现同一接口。

- 文件上传继续通过现有 `/api/v1/uploads/files` 校验和存储。
- 文档草稿只接收上传接口返回的受控文件描述，不接收浏览器传入的永久存储地址。
- 文档预览和下载通过文档资源接口再次执行文档访问校验。

## API 契约

### 查询

- `GET /api/v1/documents?q=&category=&page=&per_page=`：查询当前用户可访问的已发布文档。
- `GET /api/v1/documents/{id}`：查询文档和当前有效版本详情。
- `GET /api/v1/documents/{documentId}/versions/{versionId}/files/{fileId}?preview=true`：预览文件。
- `GET /api/v1/documents/{documentId}/versions/{versionId}/files/{fileId}`：下载文件。

### 写入

- `POST /api/v1/documents/drafts`：创建文档草稿和首个版本。
- `POST /api/v1/documents/{id}/publish`：校验草稿完整性并首次发布。

写入返回完整文档响应；重复编号返回 `409 Conflict`，找不到文档/版本/文件返回 `404`，字段缺失返回 `400`，只读 profile 写入返回明确的只读错误。

文档编号允许维护者填写；草稿创建时留空则在获得文档 ID 后自动生成 `DOC-{六位文档ID}`，例如 `DOC-000123`。自动编号和人工编号遵守同一全局唯一约束，发布后均不可直接修改。

## 仓储和数据库

- 默认 profile 使用 `InMemoryDocumentRepository`，保持现有开发安全边界。
- `local` profile 使用 `JdbcDocumentRepository`，写入 `knowledge_document`、`document_version` 和 `document_file`。
- 正式扩展 DDL 使用独立 `V1_6__document_center_schema.sql`，不修改旧表主键或旧字段，不由应用启动自动执行。
- 本地引导脚本只增量创建文档表和首期分类数据，不删除或覆盖已有资产数据。
- `document_number` 全局唯一，文档和版本写入使用乐观锁或原子状态条件，防止重复发布。

## 数据流

```text
选择文件
  -> 通用上传接口校验并返回文件描述
  -> 文档草稿接口保存文档、首个版本和文件引用
  -> 发布接口校验编号/分类/摘要/维护人/文件
  -> 原子更新文档与首版状态
  -> 检索工作台只返回已发布文档
  -> 详情接口返回当前有效版本
  -> 文件接口校验文档访问后预览或下载
```

发布失败时草稿和已上传文件继续保留；已经发布成功的文档再次调用首次发布接口返回状态冲突，不重复创建版本。

## 前端模块边界

- `features/documents/`：检索工作台、新建页、查询状态和业务展示组件。
- `pages/main/document-detail/`：独立详情工作台和文件预览。
- `services/documentService.ts`：文档 API 调用和错误映射。
- `types/document.ts`：知识文档、版本、文件、分页和请求类型。
- `App.tsx`：懒加载 `/documents`、`/documents/new` 和 `/documents/:id`。
- `AppShell.tsx`：新增文档中心导航，不改变管理与治理分组。

列表、新建和详情不共享页面级状态，只通过稳定 ID、API 契约和查询缓存协作。文档预览复用现有安全文件展示能力，但不直接依赖资产页面组件内部状态。

## 错误和恢复

- 搜索失败保留关键词和分类，并提供重试。
- 文件上传单项失败保留表单和其他已成功文件，允许移除后重试。
- 草稿保存失败保留全部本地表单值。
- 发布失败保留草稿，明确展示重复编号、缺少字段或只读环境原因。
- 预览失败只影响预览区，文档信息和文件下载入口继续可用。
- 无权限或不存在使用相同的受控错误页面，不泄露文档摘要。

## 测试策略

### 后端

- 先写 `DocumentControllerTest` 的失败测试，覆盖草稿创建、首次发布、只查询已发布、详情和文件访问。
- 写应用服务测试覆盖重复编号、草稿不完整、重复发布和分页搜索。
- JDBC 仓储测试使用本地测试配置验证文档、版本和文件的原子保存。
- 后端提交前运行直接相关测试，再运行完整 `rtk mvn test`。

### 前端

- 引入 Vitest 与 Testing Library，为文档服务参数、检索状态和新建表单发布校验编写失败测试后实现。
- 运行 `rtk pnpm lint`、`rtk pnpm typecheck` 和 `rtk pnpm build`。
- 在 `1366x768` 和 `1920x1080` 验证检索工作台、新建发布、详情预览和返回条件保持，无横向溢出和重叠。
