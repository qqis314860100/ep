# 统一检索、文档适用范围与双向关联设计

## 目标

在现有数模资产平台和文档中心基础上交付 V1.7.0：普通用户从一个入口检索数模资产与知识文档，维护者明确文档的适用范围，并在资产、标准设备模块和文档之间建立可审计的双向关系。

本版本坚持低录入负担和渐进扩展：保留现有 AppShell、资产生命周期、文档生命周期和旧数据，只扩展页面内容、应用服务、领域对象和增量数据表。

## 版本边界

V1.7.0 包含：

- 统一关键词和生产范围检索，资产与文档分区展示、独立分页。
- 文档“全局通用”“指定范围”和旧数据“范围待补充”三种存储状态。
- 一份文档配置多组完整适用范围。
- 文档与普通资产、标准设备模块资产的双向关联。
- 配套文档、适用文档、参考文档三种固定关系类型。
- 关系新增、改类和解除的审计记录。
- 文档新版本发布后，现有关联自动解析最新已发布版本。
- 文档维护页、文档详情页和资产详情页中的关联维护入口。

V1.7.0 不包含：

- 将资产与文档合并成同一个领域对象或生命周期。
- 新建独立的标准设备模块主数据表。
- 文档间引用、审批矩阵、电子签章、受控副本和生产批准。
- 自定义关系类型或由普通用户发起关联审批。
- 搜索引擎、中台级索引服务或跨系统数据同步。

## 已确认的产品决策

- 统一检索采用一个搜索入口，在同一页面分为“数模资产”和“知识文档”两个结果区。
- 文档必须明确选择“全局通用”或“指定范围”；既有文档在完成治理前标记为“范围待补充”。
- 指定范围沿用平台族、平台子类、蓝本、基地、拉线和工序段字典，一份文档可以配置多组范围。
- 带生产条件检索时，返回全局通用文档和任一完整范围匹配的文档。
- 文档可以关联普通数模资产和标记为标准设备模块的资产。
- 关联关系固定分为配套、适用和参考三类。
- 关系指向稳定的文档主体，不锁定文档版本，始终展示最新已发布版本。
- 文档新建或编辑页、文档详情页和资产详情页均可维护关系，但共用同一套权限和应用服务。
- 保留现有 AppShell、导航结构、配色和组件体系，不做整套 UI 重构。

## 领域边界

### 数模资产

数模资产继续承载三维模型、二维图纸、预览文件、生产范围和资产生命周期。现有 `AssetScope` 仍是生产和产品条件匹配的最小完整单元。

### 知识文档

知识文档继续拥有独立的草稿、发布、版本和停用状态。适用范围是文档元数据，不改变文档版本文件的不可覆盖规则。

### 标准设备模块

当前系统中的标准设备模块不是独立主数据，而是 `asset_package_ext.standard_equipment_module = 1` 的数模资产。文档关联继续引用稳定的 `drawing_id`，响应和界面根据该标志展示“标准设备模块”类型，避免建设没有业务基础的多态目标表。

### 资产文档关系

资产文档关系连接一个资产和一个文档，包含：

- `relationType`：`COMPANION`、`APPLICABLE`、`REFERENCE`。
- `createdBy`、`createdAt`。
- `updatedBy`、`updatedAt`。
- `deletedBy`、`deletedAt`：解除关系使用软删除。

解除关系不删除资产、文档、版本或文件。相同资产、文档和关系类型不能存在两个有效关系；重新关联时恢复原关系或创建新的有效记录，但审计历史必须连续可追溯。

## 文档适用范围

### 范围模式

文档使用以下存储状态：

- `GLOBAL`：全局通用，不保存具体范围行。
- `SPECIFIED`：指定范围，至少保存一条 `DocumentScope`。
- `UNCLASSIFIED`：只用于迁移后的既有文档，表示范围尚未确认。

新建文档不能选择 `UNCLASSIFIED`。既有文档再次编辑或发布新版本前，必须补充为 `GLOBAL` 或 `SPECIFIED`。后台治理可以批量补充，但不得无依据地将旧文档自动认定为全局通用。

### 同一范围匹配

一条 `DocumentScope` 包含：

- 平台族 `platformFamily`
- 平台子类 `platformVariant`
- 蓝本 `productLine`
- 基地 `baseName`
- 拉线 `productionLine`
- 工序段 `processSection`

查询中所有已填写的产品和生产条件必须由同一条范围记录同时满足。禁止用第一条范围的平台和第二条范围的基地拼接命中。未提供的查询条件不参与比较。

文档检索规则：

- 无生产范围条件时，授权范围内的 `GLOBAL`、`SPECIFIED` 和 `UNCLASSIFIED` 文档均可按关键词与分类出现。
- 有生产范围条件时，返回授权范围内的 `GLOBAL` 文档，以及存在一条完整匹配范围的 `SPECIFIED` 文档。
- `UNCLASSIFIED` 文档不参与生产范围匹配，避免被误认为适用于某条产线。
- 每份文档在一个结果区中只出现一次，即使多条范围同时命中。

## 数据结构

产品 V1.7.0 的数据库变更采用受控的 V1_11 增量迁移，不修改旧主键，不覆盖遗留来源值，不由应用在生产环境自动执行。

### `knowledge_document`

增加可兼容旧数据的 `scope_mode` 字段。迁移脚本将既有行设置为 `UNCLASSIFIED`；应用创建的新文档必须显式写入 `GLOBAL` 或 `SPECIFIED`。

### `document_scope`

新增文档范围表，字段语义与 `asset_scope_ext` 对齐：

- 主键 `id`
- `document_id`
- 六个范围维度
- `source_value_json`：治理映射时保留来源值
- 创建和更新时间

建立文档索引、平台组合索引、基地/拉线/工序组合索引，并限制同一文档下的重复范围。

### `asset_document_relation`

新增关系表：

- 主键 `id`
- `drawing_id`
- `document_id`
- `relation_type`
- 创建、更新和软删除操作信息

表只引用稳定业务 ID。标准设备模块仍使用 `drawing_id`，不使用 `target_type + target_id` 形式的万能关联字段。

### `asset_document_relation_audit`

新增追加式审计表，记录：

- 关系 ID 和操作类型 `CREATE`、`CHANGE_TYPE`、`REMOVE`、`RESTORE`
- 操作前值和操作后值
- 操作人和操作时间

关系变更和审计写入必须在同一事务内完成。

## 后端架构

### 统一检索编排

新增统一检索应用服务，依赖资产查询端口和文档查询端口，不让资产领域依赖文档领域，也不把文档并入资产仓储。

统一检索服务负责：

- 解析一次关键词、范围条件和两个分页参数。
- 调用现有资产查询与扩展后的文档查询。
- 应用访问权限和文档范围规则。
- 返回两个结构稳定、独立分页的结果区。
- 单一区域发生可恢复技术错误时保留另一区域结果，并返回该区域的受控错误状态；身份或权限上下文错误则整体失败。

现有资产和文档查询接口继续保留，文档中心维护工作台不被强制迁移到聚合接口。

### 适用范围服务

文档命令服务校验范围模式和范围行：

- `GLOBAL` 不允许携带范围行。
- `SPECIFIED` 至少包含一条有效范围。
- 新建和编辑不接受 `UNCLASSIFIED`。
- 范围值必须来自启用的数据字典；迁移治理由独立受控流程保留来源值。

范围替换使用文档乐观锁并在一个事务内完成，防止并发编辑丢失范围。

### 关联应用服务

所有页面入口共用一个关系应用服务。服务负责目标存在性、文档状态、重复关系、访问权限、软删除和审计，不在控制器或前端复制规则。

草稿文档可以预先建立关系，但草稿关系只对维护者和内容管理员可见。文档发布后，普通授权用户才能从资产详情看到对应文档。

## API 契约

### 统一检索

`GET /api/v1/search`

查询参数包括：

- `q`
- 六个范围维度
- `asset_page`、`asset_per_page`
- `document_page`、`document_per_page`

响应包含 `assets` 和 `documents` 两个分页区，每个区包含 `items`、`page`、`perPage`、`total` 和 `status`。单区失败时该区返回受控错误码和可重试标志，不能以空数组伪装成功。

### 文档范围

- 文档草稿创建和编辑请求包含 `scopeMode` 与 `scopes`。
- 文档详情返回范围模式和完整范围列表。
- 旧文档返回 `UNCLASSIFIED`，前端展示“范围待补充”，不能映射为“全局通用”。

### 双向关联

- `GET /api/v1/documents/{id}/asset-relations`：查询文档关联的资产。
- `GET /api/v1/assets/{id}/documents`：查询资产关联的已授权文档。
- `POST /api/v1/asset-document-relations`：新建或恢复关系。
- `PATCH /api/v1/asset-document-relations/{id}`：修改关系类型。
- `DELETE /api/v1/asset-document-relations/{id}`：解除关系。

新增成功返回 `201`；字段或范围无效返回 `400`；无权访问和不存在统一使用受控 `404`；重复有效关系或乐观锁冲突返回 `409`。接口不能通过错误信息泄露无权对象的名称、编号和存在性。

## 权限规则

- 普通用户只能搜索和打开授权范围内的已发布文档及其已授权关联对象。
- 文档维护者和内容管理员可以维护关系，且必须有权查看目标资产。
- 从资产详情发起维护仍执行文档维护权限，不因入口位于资产页而放宽规则。
- 草稿关系只对文档维护者和内容管理员可见。
- 搜索、详情、关系数量、文件预览和下载分别执行后端权限校验。
- 无权对象不返回名称、编号、摘要、数量、版本或文件地址。

## 前端设计

### AppShell 约束

保留当前 AppShell 的顶部栏、侧边导航、页面宽度、配色、间距和组件体系。视觉原型只用于确认信息架构，不代表替换现有外壳。

### 统一检索页

- 沿用现有资料检索入口和生产条件选择器。
- 主内容按“数模资产”和“知识文档”分为两个纵向结果区，不使用需要来回切换的页签。
- 资产结果保留缩略图、预览能力、格式和生产范围信息。
- 文档结果展示标题、编号、摘要、分类、当前版本、维护部门和范围状态。
- 两个区域独立展示总数、分页、加载、空状态、失败和重试。
- 结果类型、关系类型和范围模式使用克制的标签，不改变 AppShell 风格。

### 文档维护页

- 在现有文档表单中增加“适用方式”单选项。
- 选择全局通用时不显示范围编辑器；选择指定范围时显示可批量添加的完整范围行。
- 选择资产时支持按编号、名称、平台、基地和“标准设备模块”标志检索。
- 每条关联必须选择配套、适用或参考类型。
- 系统自动填充维护人和可推断字段，减少额外录入。

### 双向详情

- 文档详情首屏固定展示关联资产与标准设备模块，不放到评论区之后。
- 资产详情首屏信息区展示关联文档，按配套、适用和参考分组。
- 关联项展示对象类型、编号、名称、状态和当前文档版本，并提供直接跳转。
- 评论保持次级协作区；评论数量增加不影响关联信息可见性。
- 有维护权限的用户可以就地新增、改类和解除关系；普通用户只看到查看入口。

## 数据流

### 统一检索

```text
关键词与生产条件
  -> 统一检索 API
  -> 资产查询：同一 AssetScope 匹配
  -> 文档查询：GLOBAL 或同一 DocumentScope 匹配
  -> 分别执行权限过滤
  -> 返回资产区与文档区
  -> 页面独立渲染、分页和恢复
```

### 关联维护

```text
文档维护页或双方详情页发起操作
  -> 关系应用服务校验维护权限和目标访问权
  -> 校验重复、状态和并发版本
  -> 同一事务写入关系与审计记录
  -> 双方查询按权限读取关系
  -> 文档响应解析最新已发布版本
```

## 错误与恢复

- 资产或文档结果区失败时保留搜索条件和另一结果区，失败区提供单独重试。
- 范围保存失败时保留本地表单和未提交范围行，不清空文件与关联选择。
- 重复关联不创建第二条有效记录，并明确提示现有关系类型。
- 资产或文档不存在、已停用或无权限时禁止新增关系。
- 并发修改返回冲突，前端提示刷新后重试，不覆盖他人变更。
- 文档新版本发布失败时，原当前版本和现有关联继续有效。
- 解除关系失败时保持当前界面状态；成功后双方查询缓存同步失效。
- 预览失败只影响预览区域，不隐藏文档信息和授权下载入口。

## 验收场景

| 编号 | 场景 | 通过标准 |
| --- | --- | --- |
| USR-AC-01 | 统一关键词检索 | 同一页面分别返回授权资产和文档，每个对象只出现一次 |
| USR-AC-02 | 结果区独立状态 | 单一区域失败不伪装为空，也不清除另一区域结果和查询条件 |
| USR-AC-03 | 同一范围匹配 | 平台与基地位于不同范围行时文档不得命中 |
| USR-AC-04 | 全局文档 | 带生产条件检索时授权的全局通用文档仍可见 |
| USR-AC-05 | 旧文档治理 | 旧文档显示“范围待补充”，且不参与生产范围匹配 |
| USR-AC-06 | 显式范围 | 新建或编辑文档必须选择全局通用或至少一组指定范围 |
| USR-AC-07 | 双向关联 | 文档详情可进入资产，资产详情可进入最新已发布文档 |
| USR-AC-08 | 模块关联 | 标准设备模块资产可被选择并以模块类型展示 |
| USR-AC-09 | 关系类型 | 配套、适用和参考类型可新增、改类并在双方详情一致显示 |
| USR-AC-10 | 自动跟随版本 | 文档发布新版本后无需修改关系即可展示新当前版本 |
| USR-AC-11 | 安全解除 | 解除关系不删除任一对象，审计记录包含操作前后值 |
| USR-AC-12 | 权限隔离 | 无权用户不能通过搜索、详情、关系接口或数量获得对象信息 |
| USR-AC-13 | 兼容旧数据 | 增量迁移不修改旧主键、旧来源值和现有资产文件 |

## 测试策略

### 后端

- 领域和应用服务测试覆盖三种范围模式、同一范围匹配、多范围去重和旧文档行为。
- 关系服务测试覆盖普通资产、标准设备模块、重复关联、改类、软删除、恢复和审计事务。
- 控制器测试覆盖统一检索双区响应、独立分页、受控局部失败和错误码。
- 权限测试覆盖搜索、双方详情、关系数量、草稿关系和文件地址不泄露。
- 内存仓储与 JDBC 仓储使用相同的契约场景验证行为一致。
- 直接相关测试通过后运行完整后端测试套件。

### 前端

- 测试统一搜索参数映射、双区状态、独立分页和失败恢复。
- 测试范围模式切换、指定范围校验和旧文档只读提示。
- 测试关联选择、关系类型修改、解除确认和权限隐藏。
- 运行 lint、类型检查和构建。
- 在 `1366x768` 和 `1920x1080` 桌面视口验证无重叠、无横向溢出，关联信息首屏可见，AppShell 风格保持一致。

## 迁移与提交

- 生产迁移只生成受控 V1_11 增量脚本，不在开发或验证中连接生产数据库。
- 默认开发 profile 继续使用内存仓储；本地 JDBC 使用独立的本地引导和迁移结构。
- 需求与契约、后端、前端分别验证并提交，不混合无关文件。
- 提交使用中文 Conventional Commit，正文记录 `产品版本：V1.7.0`。
- 每个独立可验证版本检查通过后立即提交，前后端保持独立提交。
